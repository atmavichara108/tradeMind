# Goal — автономное доведение до результата (TradingMind)

OpenCode 2.2.1+: `/goal <objective>` — сессия работает до подтверждения
рецензентом, что цель достигнута. Хранилище общее с глобальной командой.

## Хранилище

`~/.local/state/opencode/goal.json` — переживает ходы и компакт.

## Поля цели

- **objective** — дословный текст владельца (basis: quoted)
- **criteria** — проверяемые критерии (числа, файлы, тесты, прогон)
- **kill** — условие останова (что считать провалом)
- **wip** — «один активный» (две цели одновременно запрещены)
- **status** — active / paused / done / dropped
- **evidence** — факты достижения (append-only)

## Команды

- `/goal <текст>` — поставить цель (запросит criteria и kill, если не указаны)
- `/goal show` — критерии с отметкой «проверено как?» (evidence рядом)
- `/goal done` — закрыть: таблица «критерий → проверено как? → ✓/✗»
- `/goal drop` — отменить (с причиной)
- `/goal pause` / `/goal resume`

## CLI-инвокатор (headless)

Из `opencode run` slash-команды недоступны — использовать invoker:
```
python3 ~/dotfiles/tools/goal/goal.py set "цель" --criteria "к1" "к2" --kill "останов"
python3 ~/dotfiles/tools/goal/goal.py show | done | drop | pause | resume | clear
```

## Когда ставить /goal в TradingMind

1. Многошаговые фичи: импорт/экспорт данных → проверка → коммит.
2. Исследования: прогон стратегии/бэктеста → метрики → вывод → коммит.
3. Отладка: repro → фикс → проверка живым прогоном → коммит.
4. Рефакторинг с сохранением поведения (критерий — тесты/прогоны до и после).

## Когда НЕ ставить

- Одиночный вопрос/ответ; нужен выбор владельца; scope неясен (сначала уточнить).

## Критерии — проверяемые

- ✅ «CSV-экспорт пишет файл, повторный импорт даёт идентичные данные (diff пуст)»
- ✅ «бэктест на периодах X..Y проходит без исключений, отчёт лежит в reports/»
- ❌ «улучшить стратегию» (непроверяемо — по какому критерию «улучшена»?)

## Правило каждого хода (автоматическое)

Если в goal.json есть цель со `status: "active"`:
1. Начало хода — учитывать активную цель.
2. Проверять критерии; достигнута — предложить `/goal done`.
3. kill-условие сработало — предложить `/goal drop`.

## Правила ветки (этот репо)

1. Работа — в `task/<slug>`-ветке, не в main (текущая: task/tm-import-export).
2. Цель закрывается `/goal done` только после коммита в task-ветку.
3. Гейты владельца не ослаблять: цель — только по явному слову владельца.
