Логика разделения:

- **02_Mentor** — sacred, неприкосновенный сырой источник. Только копипаста, без обработки. Это твой архив правды.
- **03_Glossary** — атомарные термины. Одно понятие = одна заметка. Короткие.
- **04_Concepts** — это уже _мысли_, принципы, законы метода. Длиннее глоссария, со связями.
- **05_Setups** — конкретные торговые ситуации с правилами входа/выхода. Самые «операционные» заметки.
- **06_Playbooks** — протоколы поведения (риск-менеджмент, правило 50/50 и т.д.).
- **07_Canvases** — где живут разборы. Канвас + рядом md-заметка с выводами.
- **08_Reflections** — твоя мыслительная лаборатория. Сюда не страшно писать «не понимаю», «кажется наставник имел в виду…», вопросы для следующего разговора.

Различие 04 vs 05 vs 06 на примере: «полоса захвата ликвидности» = Concept (что это и как устроено). «Вход в отбой от уровня после сбора стопов» = Setup (конкретный сетап с условиями). «Правило 50/50 с переносом в б/у» = Playbook (что делаешь после открытия позиции).

## Плагины: минимальный старт

Ставь в таком порядке, не больше:

1. **Templater** — обязательно. Шаблоны заметок, без него каждая новая запись это ручной ад. Дам шаблоны ниже.
2. **Dataview** — обязательно. Это твой «движок дашбордов» в Obsidian. Через него собираем динамические списки: «все сетапы со статусом active», «все термины которые я ещё не понял» и т.д.
3. **Smart Connections** — да, ставь. С Gemma 3:4b будет работать на эмбеддинги (для семантического поиска связанных заметок), это лёгкая задача, 4B модели хватит. Но для _чата_ с волтом 4B слабовата.
4. **Copilot for Obsidian** — ставь, но настрой через OpenRouter API. Для чата с волтом нужна модель помощнее (Claude Sonnet, GPT-4o, Llama 70B). 4B слишком мала, будет галлюцинировать на трейдинговой терминологии.

Не ставь пока: Smart Composer (избыточно при наличии Copilot+SC), Excalidraw (канвас Obsidian для твоих задач хватит), Tasks/Kanban (Notion остаётся дашбордом, не дублируем).

**Настройка Smart Connections с Gemma:** в настройках плагина выбираешь Local → Ollama, указываешь endpoint `http://localhost:11434`, модель эмбеддингов `nomic-embed-text` (это специально для эмбеддингов, не Gemma — её для чата держи). Запусти `ollama pull nomic-embed-text` отдельно.

**Настройка Copilot через OpenRouter:** в настройках Copilot → Custom Model → ставишь base URL `https://openrouter.ai/api/v1`, ключ из OpenRouter, модель например `anthropic/claude-3.5-sonnet` или `meta-llama/llama-3.3-70b-instruct` (дешевле). Для трейдинговых разборов бери модель не слабее Sonnet/GPT-4o, на мелких будут ошибки в логике.

## Эпистемология связей — как связывать чтобы граф не стал помойкой

Используй **типизированные ссылки через Dataview inline-поля**. Вместо просто `[[Полоса захвата ликвидности]]` пишешь:

```
уточняет:: [[Стоп-хант]]
следствие из:: [[Поведение крупных игроков]]
пример:: [[Canvases/Setups/SXP_2026-01-26]]
противоречит:: 
```

Семь типов связей которых тебе хватит на старте:

- `уточняет::` — A это частный случай B
- `обобщает::` — A это общий принцип, B пример
- `следствие из::` — A вытекает из B
- `предпосылка для::` — без понимания A не понять B
- `пример::` — конкретное проявление
- `противоречит::` — конфликт с другой идеей
- `связано::` — общая, когда нет более точного типа

Через Dataview потом легко собрать «все примеры этого концепта» или «всё что вытекает из принципа дискретного депозита».

Дисциплина: _каждая ссылка должна иметь тип_. Если не можешь подобрать тип — это сигнал что связь поверхностная, может и не надо ставить.

## Inline-поля — почему они важны для тебя

Кроме frontmatter, Dataview читает поля прямо из текста заметки. Помнишь типизированные связи которые я давал?

```
уточняет:: [[Стоп-хант]]
пример:: [[Canvases/Setups/SXP_2026-01-26]]
```

Это не просто красивая запись — это инлайн-поля. Dataview их видит. Можешь сделать запрос: «покажи все заметки где есть поле `уточняет` со ссылкой на Стоп-хант» — то есть собрать всё что является частным случаем стоп-ханта. Это и есть граф знаний с типизированными связями в действии.

Пример такого запроса в карточке `03_Glossary/Стоп-хант.md` внизу:

## Что уточняет это понятие
```dataview
LIST
FROM [[]]
WHERE contains(уточняет, this.file.link)
```


`[[]]` = «этот самый файл», `this.file.link` = ссылка на текущую заметку. Получаешь снизу автоматический список всех заметок которые ссылаются на Стоп-хант через поле `уточняет`.

## Подводные камни

**Frontmatter обязан быть валидным YAML.** Если поставишь `domain: Risk Management` без кавычек — сломается на пробеле. Пиши либо одним словом, либо в кавычках: `domain: "Risk Management"`. Templater в моих шаблонах это уже делает корректно.

**Reading View vs Editing View.** В режиме редактирования (Cmd+E переключает) ты видишь код запроса. В Reading — результат. Если кажется что Dataview «не работает» — переключись в Reading.

**Регистр в значениях имеет значение.** `type: Glossary` и `type: glossary` для Dataview разные. Договорись с собой: всё в нижнем регистре. Я в шаблонах так и сделал.

**Папки в FROM пишутся в кавычках, теги без кавычек.** `FROM "03_Glossary"` — папка. `FROM #risk` — тег. `FROM "03_Glossary" AND #risk` — комбо.

## Что сделать прямо сейчас чтобы пощупать

1. Поставь плагин Dataview, в настройках включи «Enable JavaScript Queries» (на будущее) и «Enable Inline Queries».
2. Создай тестовую заметку `03_Glossary/Тест.md` с frontmatter `type: glossary`.
3. Создай `00_Maps/Map_Glossary.md`, вставь туда LIST-запрос из выше.
4. Переключись в Reading View — увидишь Тест в списке.
5. Удали тестовую заметку — список обновился без неё.

После этого Dataview перестаёт быть магией и становится твоим основным инструментом. Все Map-файлы у тебя будут на нём.
